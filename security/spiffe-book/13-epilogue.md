# 附录 C　后记（Epilogue）

> 原书：*Epilogue*（p.192）
> 翻译策略：技术直译 + 段落重排；专有项目名、协议名一律保留英文。

> 图：一只名叫 Zero 的乌龟站在更大的龟壳之上（见 `assets/pages/page-192.png`）。

**在 SPIFFE 和 SPIRE 出现之前，组织面临一个巨大的挑战**：**采用现代基础设施实践让它们旧的安全模型崩塌了**。**外围防线变得越来越千疮百孔，与此同时，IP 地址这类网络属性对访问控制来说也不再有用**。

**SPIFFE 和 SPIRE 通过为组织所有的服务提供"唯一、密码学可验证的身份"来帮助组织应对这一挑战**。**一旦有了身份，服务就可以实现更上层的安全功能**——包括认证、加密、可观测性、授权。

**要为服务提供安全的身份，首先需要一种安全的方法来确定"它们跑在哪些 server、云实例和集群上"的身份**。**这就是我们在序言中提到的"底部的乌龟"问题**。**SPIFFE 和 SPIRE 通过"利用多种因子来提供强身份证明"来解决"底部的乌龟"问题**。

**SPIFFE 和 SPIRE 是开源项目——永远欢迎更多的力量加入！** **请访问网站 spiffe.io，并加入 SPIFFE 的 Slack 工作区——与不断壮大的用户社区互动**。

**Trust in Zero.**

—— *Zero the Turtle*，2020
